# Core and PAM: deviations, spec gaps and judgment calls

Format: **what** — spec says / official tests (generated by the 2020 Java code) do / what we implemented.

## Matching the official tests (behaviour not in, or contradicting, the spec)

- **Day counts round timestamps to the nearest hour.** Spec: silent. Tests: a maturity at
  `2013-12-31T23:59:59` accrues as if it were `2014-01-01T00:00` (minutes ≥ 30 round up), so the
  last period gets an extra day of interest. We: same (`daycount.rs`).
- **Same-instant event order uses second offsets.** Spec: "an event sequence indicator" per event
  type. Tests: each type adds 20–950 *seconds* to its timestamp before sorting, so ordering can
  interact with events seconds apart (e.g. a TD at 23:59:59). We: same (`EventType::sequence`).
- **Cycle anchors default to IED, not IED + cycle.** Spec: if `IPANX` is missing, the first IP is
  at `IED + IPCL`. Tests: the anchor is IED itself, which produces a zero-payoff IP event on the
  IED date. We: follow the tests (applies to IP, RR, FP, SC, optionality anchors).
- **End-of-month convention ignores pure-year cycles.** Spec: EOM applies to M, Q, H and Y cycles.
  Tests: only cycles with a month component (`P1M`, `P12M`), not `P1Y`. We: follow the tests.
- **Stub notation.** Spec text: `+` long stub, `-` short stub. Data/tests: `L0` = long stub
  (last regular date dropped), `L1` = short stub. We: `L0`/`L1`.
- **Termination keeps the interest rate.** Spec STF_TD_PAM sets `Ipnr = 0`. Tests: the rate stays.
  We: keep it (it has no economic effect once notional is 0).
- **Scaling multiplier.** Spec STF_SC: `(index − SCIED) / SCIED`, i.e. the *change* of the index.
  Tests: `index / SCCDD`, the index *ratio* (which is what a multiplier must be — the spec formula
  would scale a 100 → 110 index to 0.1 instead of 1.1). We: ratio. Spec bug.

## Unfinished in Java, completed per spec/dictionary

- **Accrued interest at the status date.** Java always starts at 0 (or the given `IPAC`).
  Dictionary: if `IPAC` is missing and the status date is after IED, estimate it from the last
  interest date (or IED). We: estimate in every lending type (PAM, LAM family, CLM, UMP). The
  `accruedInterest` term, when given, is signed by the contract role (terms are role-neutral).
  Official cases that assumed 0 run with `accruedInterest: 0` injected — see
  `ERRATA_ZERO_ACCRUED_INTEREST` in `src/conformance.rs` (lam18, lam21, clm03/05–11/14).
- **Fee accrued at the status date and fee basis `A`.** Java: always 0 / ignores fee basis when
  accruing. Spec: estimate, and for basis `A` accrue a pro-rata share of the fixed fee. We: spec.
- **Prepayments (PP) and penalties (PY).** Java PAM never schedules them. We: when
  `prepaymentEffect ≠ N`, PP on `S(OPANX, OPCL, MD)` (anchor default IED, MD excluded) plus observed
  PP at any other time. Amount: the observed value (signed by role), else
  `O(objectCodeOfPrepaymentModel, t) × Nt` if a model is given, else 0 (the event is still emitted);
  capped at |Nt|. PY at the same times when `penaltyType ≠ O` (zero if nothing is prepaid).
  Effect on amortizers: see loans.md.
- **Credit events (CE).** Java PAM: none. We: an observed CE sets the contract performance
  (default `DF`) and the non-performing date.
- **Settlement currency.** Java never reads `settlementCurrency`, so the FX factor is always 1.
  We: observe `CUR/CURS` when it differs from `CUR`.
- **30E/360 ISDA.** Java never passes the maturity date in, so the "last day of February at
  maturity" exception never applies. We: pass the maturity date.
- **28E/336.** Java's formula compares the end date with the *start* month's last day. We: clamp
  both days to 28.
- **Maturity payoff.** Spec POF_MD adds accrued interest and fees; Java pays notional only. We: spec,
  and also accrue interest from the last event to maturity (the spec formula forgets that term).
  Identical to Java whenever an IP falls on the maturity date (all tests).

## Spec issues (decided)

- **Purchase/termination payoffs for liabilities.** Spec POF_PRD = `R × (−1) × (PPRD + Ipac + accrual)`
  where `Ipac` is already signed by the role. For a liability (R = −1) that becomes
  `PPRD − |accrued|`, but the buyer of a liability must *receive* the accrued interest it will later
  pay out. We: `−(R × PPRD + Ipac + accrual)` and TD `R × PTD + Ipac + accrual` (PAM, LAM family,
  CLM, UMP). Three official RPL payoffs (lam04 TD, nam04 TD, lam21 PRD) encode the spec formula;
  they are accepted via `ERRATA_LIABILITY_ACCRUED_SIGN` in `src/conformance.rs`.
