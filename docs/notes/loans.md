# Amortizing loans (LAM, NAM, ANN, LAX): where spec, tests and engine differ

Each bullet says what the item is, what the ACTUS spec says, what the official tests expect (the
tests were generated by the 2020 Java reference implementation), and what this crate does.

## Shared by LAM / NAM / ANN / LAX

- **Missing `accruedInterest` at a running contract.** The spec and dictionary say to estimate the
  interest accrued from the last IP date (or IED) to the status date. The tests expect 0: Java
  leaves this as a TODO and defaults IPAC to 0. We follow the tests for the LAM family, so a missing
  IPAC means 0.
  **Inconsistent with PAM**, which still estimates. Needs a decision: either estimate everywhere
  and treat the tests as wrong, or use 0 everywhere.
- **Sign of `accruedInterest`.** Terms are role-neutral, so for the LAM family we apply it as
  `R·IPAC`, as Java does. PAM uses the term unsigned. Same decision as above.
- **PR redemption is capped at the outstanding notional.** `red = Prnxt − R·max(0, |Prnxt| − |Nt|)`.
  The spec has no cap; the tests rely on it on the last PR before MD.
- **PR accrues interest.** In the spec, `STF_PR` leaves `Ipac` alone in some variants. The tests
  (and we) accrue `Ipac += Y·Ipnr·Ipcb` at every PR.
- **The MD event is BDC-shifted** in the LAM family (it is not in PAM). Both follow the tests.
- **Scaling index (SC).** The spec uses `(obs − SCIED)/SCIED`. Java and this engine use
  `obs / SCCDD`, the formula inherited from PAM.
- **`fixingDays`** is a Java alias for the fixing period. We accept it as `fixingPeriod`.

## Interest calculation base (ICB)

- **Default ICB.** Java LAM parses a missing ICB as null, which gives ipcb = 0 in some paths. We
  default to `NT` (the dictionary default); lam29–31 pass.
- **Which events update `Ipcb` to the new notional:**
  - LAM: PR updates it for every ICB except `NTL`, including `NTIED`. The spec says only for `NT`;
    the tests need the Java rule.
  - NAM / ANN: PR updates it only for `NT`.
  - IPCI updates it for every ICB except `NTL`.
  - LAX PR/PI updates it for every ICB except `NTL` (Java `STF_PR_LAX2` / `STF_PI_LAX2`).

## LAM

- **Derived maturity when MD is missing.** The anchor-before-status-date branch in Java is buggy.
  We take the last PR date before SD (or the PR anchor if that is ≥ SD) and add
  `ceil(NT/PRNXT)` cycles, or one fewer when starting from the anchor. EOM adjustment applies.
- **Initial PRNXT when missing:** NT divided by the number of PR dates after SD, maturity
  included (spec).

## NAM

- **Derived maturity.** The spec computes it from the per-cycle principal part
  `PRNXT − Y(last, last+PRCL)·IPNR·NT`. Java's else-branch is buggy. We follow the spec, then
  shift the result with the BDC as the tests expect.
- **Redemption:** `Prnxt − R·(Ipac + accrued since last event)`, capped at |Nt|.

## ANN

- **Initial PRNXT.** The spec formula is unfinished ("todo"). We implement the annuity formula
  from Java: `(Nt + Ipac + Y(sd, t1)·r·Nt) · Π / (1 + Σ)` over the remaining PR dates, through
  AMD, or MD when AMD is absent.
- **PRF events are not in the spec.** Java adds one at every RR time to re-fix the annuity, plus
  one at `PRANX − 1 day` when PRNXT is not given. Special case (ann09): if that date is before
  IED, there is no PRF event; the amount is fixed at IED over PR dates ≥ IED instead.

## LAX

- **Maturity.** Java uses the `to` argument of `schedule` as the maturity whenever it is given.
  Every LAX test passes a `to`, and 14 of the 18 have no MD. We do not let a query horizon change
  the contract. Instead:
  - use MD if it is given;
  - otherwise derive it from the principal segments: walk the segments, apply +payment (INC) or
    −payment (DEC) per event, and stop at the event where the notional reaches ≤ 0;
  - with no segment cycles at all, use the last anchor (Java);
  - then BDC-shift the result.

  This matches every test's `to`. Java's derivation loop handles only some segment layouts (the
  `prAnchor.size()-2 == index` special case).
- **PRF events.** The spec lists them for LAX; Java emits none. We emit none, since
  PR/PI amounts come straight from the array terms and there is nothing to re-fix.
- **PI cap.** Java applies the PR cap (`max(0, |pp| − |Nt|)`) to increases as well, which makes
  no sense for a drawing. We follow the spec: `PI` adds `R·ARPRNXT[i]` and pays `−R·Nsc·ARPRNXT[i]`.
  The tests cannot tell the difference.
- **Variable reset (RR).** `ARRATE[i]` acts as an extra spread:
  `target = obs·RRMLT + RRSP + ARRATE[i]`, then the period and life caps/floors (Java;
  lax18 confirms it).
- **Fixed reset (RRF).** `target = ARRATE[i]·RRMLT + RRSP`, then caps and floors (Java). The spec
  sets the rate to `ARRATE[i]` directly. The two agree with the default multiplier and spread.
- **`nextResetRate` with arrays.** Java turns the first reset after SD into a no-op (`STF_RRY`),
  and only looks at the last segment's events (a bug). We set the rate to NRR at the first reset
  after SD across all segments, matching PAM/LAM's RRF. No test covers this.
- **Capitalization end with an IP array.** Java turns the IPs before CED into IPCI and drops the IP
  at CED, but never adds the IPCI at CED (so interest from the last IPCI up to CED is not
  capitalized). We use the PAM/LAM rule: IPs at or before CED become IPCI, and there is an IPCI at
  CED. No test covers this.
- **Array parsing.** Each array term may be a JSON array, a scalar, or a `"[a, b]"` string. A
  missing cycle array means each segment is a single event at its anchor. `arrayFixedVariable`
  accepts `F`/`FIX`/`V`/`VAR`.
